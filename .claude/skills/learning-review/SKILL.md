# 学びレビュー

report-session が各レポート末尾に残した学びを横断で読み、次の 3 つを行う:

1. 学びマップ `claude-report/_learning-map.md` の更新 — テーマ別に集約した横断参照ハブ
2. Claude の動作改善への反映 — CLAUDE.md / `.claude/rules/` / skills / hooks / settings への落とし込み
3. トリアージキュー `claude-report/_learning-triage.md` のチェックオフ

## 入力の収集

1. vault を解決する: `VAULT=$(obsidian vault | awk -F'\t' '/^path\t/{print $2}')`
2. `$VAULT/claude-report/_learning-triage.md` の未チェック行（`- [ ]`）を対象レポートとする
   - キューが無い・空のときは `grep -l '#learn/' "$VAULT/claude-report"/*.md` で全対象を拾ってよい
   - ユーザーが範囲を指定したら（「最近の分だけ」「flaky 関連だけ」等）それに従う
3. 対象レポートの学び項目を読む。対象が多い場合（目安 10 レポート超）は Explore サブエージェントに「各ファイルの `#learn/` タグ付き箇条書きを出典ファイル名付きで抜き出して返す」よう委譲し、メインコンテキストをレポート本文で溢れさせない
4. 既存の `_learning-map.md` を Read する（既存テーマへの追記か新テーマかを判断するため。無ければ新規作成）

## 分析

学びをテーマでクラスタリングする。特に注目する軸:

- **複数レポートで繰り返し現れるパターン** — 再発している = 仕組み化（ルール・skill・hook）の最有力候補
- **ユーザーによる訂正・好みの表明** — 恒久ルール化の候補
- **ツール・コマンドの失敗と回避策** — rules / skill への追記候補
- **単発でも影響が大きいもの** — 事故級の失敗（完了捏造・データ破損経路など）は 1 回でも反映候補

各テーマについて反映先を判断する:

| 学びの性質 | 反映先 |
|---|---|
| 全プロジェクト共通の振る舞い | ユーザー global CLAUDE.md（実体 `~/.dotfiles/.claude/CLAUDE.md`） |
| 特定プロジェクト固有 | そのプロジェクトの CLAUDE.md / `.claude/rules/` |
| 特定の作業手順・ワークフロー | 既存 skill の改修、または新 skill の提案 |
| 毎回自動で発動すべきチェック | hooks / settings.json（update-config skill の領分） |
| 知識・原則（#learn/knowledge） | 原則として学びマップへの整理のみ（反映提案は #learn/agent が主対象） |

「ルール化しない」判断も成果として扱う。一度きりの状況依存の学び・既に反映済みの学び・ルール化するとノイズになる学びは「見送り」として理由付きで記録する。

## 反映の実行

- 提案はテーマ単位でまとめて提示し、AskUserQuestion（multiSelect）で採否を確認してから適用する。ユーザーと対話できない文脈（fork・自動実行）では適用せず、提案リストを最終出力にする
- `~/.claude` 配下を変更するときは dotfiles 規約に従う: 実体 `~/.dotfiles/.claude/` を編集して `~/.dotfiles` でコミットする。symlink を直接書き換えて壊さない（詳細はユーザー global CLAUDE.md）
- skill の新設・改修が大きくなる場合は skill-creator の利用を検討する

## 学びマップの更新

`$VAULT/claude-report/_learning-map.md` を更新する。構造:

```markdown
# Claude 学びマップ

## エージェントの振る舞い

### テーマ名（例: 外部書き込みと permission classifier）

テーマの要約（2〜4 文）。何が繰り返されていて、どうするべきか。

- 個別の学びの一行要約 [[出典レポートのファイル名]]
- ...

反映: `~/.dotfiles/.claude/CLAUDE.md` に反映済み（2026-07-10）／ 未反映 ／ 見送り（理由）

## 知識・原則

### テーマ名

（同じ構造）
```

- マップは**要約 + 出典 wikilink** に留める。レポート本文の複製はしない（正本はレポート側）
- 既存テーマに合う学びはそのテーマへ追記し、合わなければ新テーマを立てる。テーマが育ちすぎたら分割する
- 「反映:」行は反映の実行結果に合わせて必ず更新する（未反映のまま残っているテーマが次回レビューの積み残しとして見えるように）

## キューのチェックオフ

処理したレポートの行を `- [x]` にし、行末に ` → ` で処理結果を追記する:

```markdown
- [x] [[20260701_224019 ...]] — agent 11 / knowledge 8 → map 3 テーマ / CLAUDE.md 反映 1 / 見送り 2
```

## 締め

最終出力には次を含める: 更新した学びマップのテーマ一覧（新規/追記の別）、反映を適用したファイル、見送りとその理由、キューの残件数。このレビュー作業自体を report-session でレポート化はしない（成果物はマップと反映先に残る）。
