# PR 説明文の生成

リポジトリのテンプレートと個人ルールを実行時に読み込み、以下の原則に従って PR 説明文を生成する。

## Steps

1. デフォルトブランチを確認する: `gh repo view --json defaultBranchRef -q .defaultBranchRef.name`（gh が使えなければ `git symbolic-ref refs/remotes/origin/HEAD`）
2. `git log <default-branch>..HEAD --oneline` と `git diff <default-branch>... --name-only` で変更のスコープを把握し、必要に応じて変更ファイルを読んで文脈を理解する
3. リポジトリのテンプレートを読む: `.github/PULL_REQUEST_TEMPLATE.md`（無ければ下記フォールバック構成を使う）
4. 個人ルールを読む（存在するものだけ）:
   - `~/.claude/pr-description/rules.md` — 全リポジトリ共通の個人ルール
   - `~/.claude/pr-description/repos/<org>/<repo>.md` — リポジトリ別の個人ルール。`git remote get-url origin` から org/repo を導出する
5. 優先順位「リポジトリ別個人ルール > 共通個人ルール > リポジトリテンプレート」で統合し、説明文を生成・出力する。個人ルールはテンプレートのセクション取捨（例: チェックリストの省略）や表記規約を上書きできる

## 情報の取捨選択

**説明文は「コードの抽象（目的・影響範囲）＋コード外の文脈（判断根拠・運用）」で構成する。diff と同じ抽象度の再記述はしない。**

説明文はレビュワーの判断材料になる情報だけに絞る。基準は「diff を読めばわかるか」:

- **書かない**: diff を読めばわかること。リソース定義や設定値の逐条説明、実装の細部、変更ファイルの網羅列挙など。コード内コメントに書いた注意書きの再掲も不要（必要なら「コード内 TODO 参照」のように参照で済ませる）
- **書く**: コードから読み取れないこと。変更の目的・背景、設計判断とその根拠（なぜその選択をしたか、安全と判断した理由）、影響範囲、費用・リスク・運用への影響、マージ運用の判断（セルフマージする場合はその根拠）
- 詳細な経緯や比較検討に正本（ADR・設計ドキュメント・issue）があるなら、説明文には結論 1 行 + リンクだけ残して委譲する

## Rules

- 変更内容の箇条書きは「何を変えたか」を端的に記述し、冗長な言い回しや自明な実装の細部は省く。1 行に収める必要はなく、説明が必要なら複数行にわたってよい。変更の根拠・判断の背景はレビュワーが妥当性を判断できるよう残すこと
- 該当事項がない任意セクション（スコープ外・相談事項など）は省略する
- issue 番号などの必須情報が不明な場合はプレースホルダ（`#XXX` 等）のままにして、ユーザーに確認を促す
- 出力はコードブロックで囲まず、そのままテキストとして出力する

## フォールバックテンプレート

リポジトリにテンプレートが無い場合は次の構成を使う:

```
### 概要

<1〜2 行で変更の目的と概要>

### 変更内容

<箇条書きで変更内容を簡潔に説明する>

### スコープ外・相談事項（任意）
```
